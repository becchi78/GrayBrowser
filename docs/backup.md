# データベースのバックアップと復元

タグ・レーティング等のメタデータは `app.db` にのみ保存されています。破損や誤操作に備え、GrayBrowser は `app.db` のスナップショットを自動・手動で取得します。ローカルディスク内のバックアップのみを対象とし、クラウド連携はありません。

## 保存先

`<アプリのデータフォルダ>/backups/`(`app.db` と同じフォルダ直下)。

ファイル名は `app-<種別>-<YYYYMMDDTHHMMSSZ>.db` です。時刻は UTC です。

| 種別 | 取得タイミング | 保持世代 |
| --- | --- | --- |
| `premigrate` | 起動時、未適用のスキーママイグレーションがある場合に、適用の直前に自動取得 | 3 |
| `manual` | メニュー「ファイル > データベースをバックアップ」を実行したとき | 10 |

- 世代数は種別ごとに別枠で数え、超過分は古いものから削除します。手動バックアップを繰り返してもマイグレーション前の退避は押し出されません。
- 定期(毎日など)の自動バックアップはありません。
- 新規作成直後の空のデータベースではバックアップを取りません。

## 取得方式

SQLite の `VACUUM INTO` で整合したスナップショットを一時ファイルに書き出し、`PRAGMA quick_check` で検証してから正式な名前にリネームします。検証に失敗したバックアップは残らず、既存の世代も削除されません。

- 手動バックアップの結果(保存先、または失敗理由)はダイアログで表示されます。
- マイグレーション前の自動バックアップが失敗した場合は `logs/` のログに記録するだけで、起動は継続します。

## 復元手順

1. GrayBrowser を終了する。
2. `app.db`、`app.db-wal`、`app.db-shm` を別の場所へ退避する(削除せず保管しておく)。
3. `backups/` から戻したいバックアップを選び、`app.db` という名前でデータフォルダにコピーする。`app.db-wal` と `app.db-shm` は残さない。
4. GrayBrowser を起動する。

古いバージョンのバックアップを戻した場合、起動時にマイグレーションが適用されます(このときも `premigrate` バックアップが取られます)。
