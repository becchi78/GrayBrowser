# 開発者モード(Draft版の受け取り)

開発者モードをオンにすると、安定版として公開する前の「Draft版」を、アプリ内の更新で受け取れるようになります。新しい機能を早めに試したい方、動作確認に協力していただける方向けの機能です。通常の利用では、オンにする必要はありません。

## Draft版とは

- 安定版として公開する前の版で、動作確認用です。**不具合が残っている場合があります**。
- 版数は、これから公開される安定版と同じです(`-dev` などの付いた別の版数ではありません)。
- 確認が済んで安定版として公開される版と、同じインストーラーです(Draft の Release のビルドを、先行して受け取る形です)。GitHub の Releases の `dev` という Pre-release に置かれます。
- 公開前の人の確認より先に届くことがあります。

## 使い方

1. 設定ダイアログの「開発者モード」をオンにします。オンの間は、画面にそれを示すバッジが表示されます。
2. 「ヘルプ > 更新の確認...」(または起動時の更新確認)で、更新を確認します。
3. 安定版とDraft版の両方を確認し、**新しい版のほう**が提示されます(同じ版なら安定版)。Draft版の更新には、公開前の確認中のビルドである旨の案内が表示されます(下の「Draft版かどうかの見分け方」を参照)。

オフに戻すと、以降は安定版だけが提示されます。すでに入れたDraft版は、そのまま使い続けられます。安定版に戻したい場合は、より新しい安定版が公開されるのを待つか、[Releases](https://github.com/becchi78/GrayBrowser/releases) から安定版のインストーラーを手動で入れてください。

## Draft版かどうかの見分け方

- **更新ダイアログ**: 提示された版がDraft版のときは、ダイアログのタイトルの下に「Draft版」と表示され、「Draft版です。公開前の確認中のビルドで、問題がなければ、このビルドが安定版として公開されます。動作確認用のため、不安定な場合があります。」という案内が枠付きで出ます(確認の結果によっては、このビルドが公開されないこともあります)。安定版のときは「安定版」と表示され、この案内は出ません。起動時の更新通知にも、Draft版のときは「(Draft版)」と付きます。
- **バージョン情報**(ヘルプ > バージョン情報): 開発者モードがオンのときだけ、「この版の状態」が表示されます。開くたびに確認します。
  - 「Draft版」: いま動いている版が、公開済みの最新の安定版より新しい。
  - 「公開済みの安定版」: いま動いている版が、公開済みの最新の安定版と同じか、それより古い。
  - 「確認できません」: 公開済みの安定版の版を取得できなかった(オフラインなど)。
- **診断情報**: 同じ判定が `Release status:` の行に入ります(`draft (not yet published)` / `published stable` / `unknown`)。

判定は、動いている版と、公開済みの最新の安定版(`releases/latest`)の版との比較だけで行います。

## 調査に使えるツール

開発者モードがオンの間は、不具合の調査に役立つ次のツールが使えます。オフのときはメニューに出ません。変更を伴う操作や、パスを含む情報は、アプリ側でも実行を断ります(診断情報・ログレベル・ログフォルダ・開発者ツール・最適化・スキャン診断)。

- **診断情報**(ヘルプ > 診断情報...): アプリの版、データベースのスキーマ版、FFmpeg / FFprobe の版、WebView2 の版、OS、データベース・データ・ログの場所をまとめて表示し、「コピー」でクリップボードへ送れます。ユーザー名を含むパスは `%LOCALAPPDATA%`、`%APPDATA%`、`%USERPROFILE%` に置き換えますが、不具合の報告に貼る前に内容を確認してください。
- **ログレベルとログフォルダ**(ヘルプ > 動作ログ...): ログレベルを info(既定)・debug・trace から選べます。debug 以上では、FFmpeg / FFprobe を実行したコマンドと、その標準エラー出力(末尾のみ)もログに残ります。動作ログのファイルには動画のパスが含まれる場合があるため、共有する前に確認してください。「ログフォルダを開く」で、ログの保存先をエクスプローラーで開けます。選んだレベルが効くのは開発者モードがオンの間だけで、オフに戻すと即座に info に戻ります(選んだ値は覚えていて、次にオンにしたときに再び使われます)。
- **開発者ツール**(ヘルプ > 開発者ツールを開く): WebView の開発者ツール(DevTools)を開きます。開発者モードがオフのときは、F12・右クリックの「検証」・Ctrl+Shift+I では開かないように設定していますが、実機での確認は済んでいません(確認できるまで、オフでも開けないとは断定しません)。F12 と右クリックはウィンドウ設定で、Ctrl+Shift+I は権限の拒否で止めています。
- **データベースツール**(ヘルプ > データベースツール...): データベースのファイルサイズ・ページ数・空きページ数を表示します。「整合性チェックを実行」は、データベースが壊れていないかを調べるだけで、何も変更しません。「最適化を実行...」(VACUUM)は、空き領域を回収してファイルを小さくします。次の点に注意してください。
  - 実行前に確認ダイアログが出ます。自動で手動バックアップ(`backups/` フォルダ、種別 `manual`)を取り、**バックアップに成功したときだけ**最適化を行います。バックアップに失敗したときは、最適化を行いません。
  - 最適化には、データベースのサイズの約2倍(バックアップ分と作り直し分)と余裕の空き容量が要ります。足りないときは、バックアップも取らずに断ります。
  - 最適化そのものは元に戻せません。戻すときは、事前のバックアップから復元してください([データベースのバックアップと復元](backup.md))。
  - 空き容量の見積もりは、データベースと `backups` フォルダが同じドライブにあること、実行直前のチェックポイントで WAL が切り詰められることを前提にしています。SQLite の一時ファイルの置き場(TEMP)のドライブは確認しません。チェックポイントが切り詰め切れなかったときは、表示されるサイズの変化が実際と合わないことがあります。
  - 実行前のバックアップは手動バックアップとして保存されます。手動バックアップは 10 世代まで保持され、古いものから消えるため、最適化を繰り返すと、以前に取った手動バックアップが消えます。残したいバックアップは別の場所へコピーしてください。
  - 実行中は、データベースへの書き込みを止めます(書き込みの権利を、バックアップと最適化が終わるまで保持します)。タグの割り当てなど、メインスレッドで動く書き込みの操作は、その間待たされます。実行中は画面を覆う処理中の表示が出て操作できないようにしている、という前提で成り立っています。データベースが大きいと時間がかかり、その間は、スキャンなども待たされることがあります。ほかの処理が書き込み中で 30 秒たっても始められないときは、実行せずに中止します。
- **スキャン診断**(ヘルプ > スキャン診断...): 直近の手動スキャンの、段階別の所要時間(列挙、検証・ハッシュ・登録、消えた動画の確認)とその割合、件数、サムネイル・メタデータ生成の件数・合計時間・失敗数、失敗したファイルの一覧を表示し、「コピー」でクリップボードへ送れます。読めなかったファイル(件数もログも残らないもの)、未登録のファイル(理由つき)、サムネイル・メタデータの生成に失敗したファイルを載せます。一覧は種類ごとに 200 件までで、超えた分は件数だけです。ユーザー名を含むパスは置き換えますが、貼る前に内容を確認してください。結果はメモリ上だけにあり、アプリを終了すると消えます。スキャンの前は「まだスキャンが実行されていません」と表示します。サムネイル・メタデータの集計は、そのスキャンを始めてからの分です。

## データのバックアップについて

Draft版の更新でデータベースの構造(スキーマ)が変わる場合、更新後の最初の起動で、移行の直前にデータベースが自動でバックアップされます(種別 `premigrate`、`backups/` フォルダ)。保存先、保持世代、復元手順は [データベースのバックアップと復元](backup.md) を参照してください。

次の点に注意してください。

- 自動バックアップが取られるのは、**スキーマの移行がある更新のとき**だけです。移行がない更新では取られません。
- 大切なデータがある場合は、Draft版に更新する前に、「ファイル > データベースをバックアップ」で手動のバックアップを取っておくことをお勧めします。
- Draft版で新しい構造に移行したデータベースを、古い版に戻して使えるとは限りません。戻す場合は、バックアップから復元してください。
- データベースが、動かしているアプリより新しい構造になっていると、GrayBrowser は起動を中止してダイアログで案内します(データベースには何も書き込みません)。Draft版から安定版へ戻すときは、先にバックアップからの復元が必要です([アプリより新しいデータベースを開いたとき](backup.md#アプリより新しいデータベースを開いたとき) を参照)。

## 更新の安全性

Draft版も、安定版と同じ公開鍵による署名の検証を通ったものだけが適用されます。更新の確認先はアプリに固定されていて、設定やフロントエンドから変更することはできません。仕組みの詳細は [リリースの仕組み](dev/release-process.md) を参照してください。
